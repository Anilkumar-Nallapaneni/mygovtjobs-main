# Deploy backend API — Railway & Render step-by-step

Host the FastAPI backend at **https://api.livegovtjobs.com** for admin dashboard, server-side search, alerts API, and Razorpay billing.

---

## Prerequisites

- [ ] Supabase project with jobs data (`npm run supabase:test`)
- [ ] `backend/.env` working locally (`npm run db:test`)
- [ ] Admin key generated: `npm run admin:key:generate`
- [ ] Git repo pushed to GitHub

---

## Option A — Railway (recommended)

### Step 1: Create project

1. Open [railway.app](https://railway.app) → sign in with GitHub.
2. **New Project** → **Deploy from GitHub repo**.
3. Select `mygovtjobs-main` (this repo).
4. Railway detects `railway.toml` and builds `backend/Dockerfile`.

### Step 2: Environment variables

In Railway → your service → **Variables**, add:

| Variable | Value |
|----------|--------|
| `APP_ENV` | `production` |
| `DATABASE_URL` | Supabase **Transaction pooler** (`postgresql+asyncpg://postgres.REF:PASSWORD@...pooler.supabase.com:6543/postgres`) |
| `SUPABASE_URL` | `https://YOUR_REF.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → `service_role` |
| `ADMIN_API_KEY` | from `npm run admin:key:generate` |
| `CORS_ORIGINS` | `https://www.livegovtjobs.com,https://www.livegovtjobs.com` |
| `ALLOW_INSECURE_ADMIN` | `0` |
| `ALLOW_FALLBACK_JSON_EXPORT` | `0` |
| `PDF_OCR_ENABLED` | `0` |
| `RESEND_API_KEY` | (optional) for alert emails |
| `ALERT_FROM_EMAIL` | `My Govt Jobs <alerts@livegovtjobs.com>` |
| `RAZORPAY_KEY_ID` | (optional) see [RAZORPAY.md](./RAZORPAY.md) |
| `RAZORPAY_KEY_SECRET` | |
| `RAZORPAY_WEBHOOK_SECRET` | |
| `SENTRY_DSN` | (optional) |

### Step 3: Deploy & health check

1. Railway auto-deploys on push to connected branch.
2. **Settings → Networking → Generate Domain** (e.g. `mygovtjobs-api-production.up.railway.app`).
3. Test:
   ```bash
   curl https://YOUR-RAILWAY-DOMAIN.up.railway.app/health
   ```
   Expect: `"status":"ok"` and `"database":{"connected":true}`.

### Step 4: Custom domain

1. **Settings → Networking → Custom Domain** → add `api.govtjobs.me`.
2. At your DNS provider (where `govtjobs.me` is managed):
   ```
   Type: CNAME
   Name: api
   Value: <railway-target-hostname>
   ```
3. Wait 5–15 minutes for TLS.
4. Verify:
   ```bash
   curl https://api.livegovtjobs.com/health
   ```

### Step 5: Connect frontend

```bash
# Add to frontend/.env.local:
VITE_API_URL=https://api.livegovtjobs.com

npm run vercel:env:push:live
npm run vercel:deploy
```

## Option B — Render

### Step 1: Blueprint deploy

1. [render.com](https://render.com) → **New → Blueprint**.
2. Connect GitHub repo — Render reads `render.yaml`.
3. Service name: `mygovtjobs-api`.

### Step 2: Secrets

In Render dashboard, set sync=false variables (same table as Railway above):

- `DATABASE_URL`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ADMIN_API_KEY` (auto-generated by blueprint, or paste yours)
- Alert + Razorpay vars as needed

### Step 3: Custom domain

1. **Settings → Custom Domains** → `api.govtjobs.me`.
2. Add CNAME at DNS provider per Render instructions.
3. `curl https://api.livegovtjobs.com/health`

### Step 4: Vercel

Same as Railway Step 5.

## Post-deploy checklist

```bash
npm run go-live:check
curl https://api.livegovtjobs.com/health
curl https://api.livegovtjobs.com/api/billing/config
```

| Check | Expected |
|-------|----------|
| `/health` | `"status":"ok"` |
| `/api/billing/config` | `{"enabled":true,...}` when Razorpay keys set |
| `/admin` on site | Dashboard loads with admin key |
| Navbar search | FTS results when `VITE_API_URL` set |

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `503` on `/api/jobs` | `DATABASE_URL` wrong — use pooler port **6543**, prefix `postgresql+asyncpg://` |
| CORS errors in browser | Add `https://www.livegovtjobs.com` to `CORS_ORIGINS` |
| Admin 401 | Match `ADMIN_API_KEY` in browser session with Railway/Render env |
| Cold start slow (Render free) | Upgrade plan or use Railway |
